# 字节码和机器码关系

Q: 字节码和二进制机器程序(机器码)关系

可以把 **字节码、二进制机器程序、机器码** 的关系理解成“中间语言”和“CPU 最终执行语言”的关系。

runner2011: 字节码是在机器码上层抽象，独立于硬件specific，由虚拟机翻译运行。机器码是根据硬件（cpu）架构生成，硬件specific, 原生代码（native binary）。

### 1. 字节码是什么

**字节码（Bytecode）是一种中间指令集**，通常不是直接给真实 CPU 执行的，而是给某个**虚拟机**执行。

比如 Java：

```text
Java 源代码
Hello.java
    ↓ javac 编译
Java 字节码
Hello.class
    ↓ JVM 解释 / JIT 编译
机器码
    ↓
CPU 执行
```

例如 Java 源码：

```java
int c = a + b;
```

编译后可能变成类似 JVM 字节码：

```text
iload_1
iload_2
iadd
istore_3
```

这里的 `iadd` 是 **JVM 的指令**，不是 Intel x86 或 ARM CPU 的指令。

---

### 2. 二进制机器程序是什么

通常所谓的**二进制机器程序 / 本地程序（native binary）**，里面核心是针对某种真实 CPU 编译出来的**机器码**。

例如 C：

```text
C 源代码
hello.c
    ↓ GCC / Clang
x86-64 机器码
    ↓
可执行文件 hello / hello.exe
    ↓
CPU 直接执行
```

例如：

```c
c = a + b;
```

可能编译成 x86-64 汇编：

```asm
mov eax, edi
add eax, esi
```

而 CPU 实际看到的是这些指令对应的二进制编码，例如：

```text
89 F8
01 F0
```

CPU 能直接理解这些机器指令。

---

### 3. 最容易混淆的一点：字节码其实也是“二进制”

“字节码”和“二进制”并不是严格对立的概念。

例如：

```text
Hello.class
```

这个 Java 字节码文件本身也是一个**二进制文件**。

所以更准确的区分应该是：

| 类型       | 给谁执行               | 是否依赖具体 CPU |
| -------- | ------------------ | ---------- |
| 源代码      | 编译器/解释器            | 否          |
| 字节码      | 虚拟机，如 JVM          | 通常否        |
| 机器码      | 真实 CPU             | 是          |
| 可执行二进制程序 | 操作系统加载，CPU 执行其中机器码 | 是          |

也就是说：

> **字节码是二进制的一种，但通常不是 CPU 原生机器码。**

---

### 4. 为什么还要多一层字节码？

主要原因之一是**跨平台**。

如果直接编译成机器码：

```text
C代码
 ├→ x86-64 机器码
 ├→ ARM64 机器码
 └→ RISC-V 机器码
```

不同 CPU 需要不同版本。

Java 则可以：

```text
             Hello.class
                  │
        ┌─────────┼─────────┐
        ↓         ↓         ↓
     x86 JVM   ARM JVM   RISC-V JVM
        ↓         ↓         ↓
    x86机器码  ARM机器码  RISC-V机器码
```

`.class` 字节码基本不用因为 CPU 不同而重新编译，只需要对应平台有 JVM。

这就是 Java 经典的：

> **Write Once, Run Anywhere**

---

### 5. JVM 最后还是要变成机器码吗？

大多数情况下，**最终还是要落到 CPU 能执行的机器指令上**。

主要有两种办法：

**解释执行：**

```text
字节码
  ↓
JVM 读取一条
  ↓
理解这条指令是什么意思
  ↓
执行对应操作
```

**JIT（即时编译）：**

```text
字节码
  ↓
JIT 编译器
  ↓
当前 CPU 的机器码
  ↓
CPU 直接执行
```

现代 JVM 通常是两者结合。

所以可以粗略理解为：

```text
.java
  │
  │ javac
  ↓
.class
Java 字节码
  │
  │ JVM / JIT
  ↓
x86 / ARM 等机器码
  │
  ↓
CPU
```

### 一句话总结

**源代码是给人写的，字节码是给虚拟机看的，机器码是给 CPU 看的；字节码本身也通常以二进制形式存储，但它不等于 CPU 的原生机器码。**
